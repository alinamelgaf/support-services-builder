# SSB — аудит установки PWA и обновлений без переустановки

12 ноября 2026 г. · Локальная ветка `dev` · Коммит `dce0db4`

## Что выяснилось

В Windows найдены ярлыки **Support Services Builder** и **Support Services Builder (1)**. Первый использует рабочий идентификатор Chrome `ibcoalinnfibkmfkgeggnhklpolnjjkh` в обычном профиле. Второй использует другой `app-id` и отдельный профиль, оставшийся от предыдущей проверки выпуска. Рабочие ярлыки и существующая тестовая запись сохранены.

Наиболее вероятная причина запуска во вкладке — выбор старой записи либо настройка браузера для открытия установленного приложения во вкладке. Конкретную ранее нажатую запись подтвердить не удалось. Работоспособность команды «Открыть в приложении» согласуется с тем, что рабочая установка сохранилась. Изменения идентичности между опубликованными версиями не обнаружено.

Прежняя проверка запуска через DevTools не различала вкладку и отдельное окно. Воспроизведено, что программная установка с настройками по умолчанию может открыть вкладку. Теперь тест задаёт режим отдельного окна один раз при установке, затем проверяет фактический `display-mode: standalone` при запуске до обновления и после перезапуска браузера. [Документация DevTools Protocol](https://chromedevtools.github.io/devtools-protocol/tot/PWA/)

## Идентичность

| Параметр | Опубликованные 1.1.0 и 1.2.0 | Локальная правка |
|---|---|---|
| URL манифеста | `https://ssb.melgaf.com/manifest.webmanifest` | Тот же путь |
| `id` | Поле отсутствует. Вычисляемый идентификатор `https://ssb.melgaf.com/` | Явное `"/"` разрешается в тот же идентификатор |
| `start_url` | `"./"`, корень рабочего сайта | `"./"` |
| `scope` | `"./"`, корень рабочего сайта | `"./"` |
| `display` | `"standalone"` | `"standalone"` |

Сборка копирует манифест по стабильному пути. Версия используется в имени кеша Service Worker и в шапке приложения. Идентификатор PWA от неё не зависит. Механизм обновлений Service Worker сохранён. В Chrome и Edge значение, вычисленное браузером, совпало до и после обновления на одном тестовом адресе. [Спецификация Web App Manifest](https://w3c.github.io/manifest/#id-member) · [Руководство Chrome по миграции на явный id](https://developer.chrome.com/docs/capabilities/pwa-manifest-id)

## Результаты

Все проверки обновления выполнены на изолированных адресах и синтетических данных. Номер 1.2.1 использован для локального сценария перехода.

| Сценарий | Chrome 157.0.8103.51 | Edge 157.0.4341.46 |
|---|---|---|
| Переход с опубликованной 1.1.0 и с 1.2.0 на локальную сборку с явным `id` | Обе установки сохранились, черновики восстановились | Обе установки сохранились, черновики восстановились |
| Повторный запуск после закрытия приложения и перезапуска браузера | Отдельное окно, прежний идентификатор, сохранённый черновик | Отдельное окно, прежний идентификатор, сохранённый черновик |
| Повторный запуск через реальные `.lnk` Windows | Исходный ярлык «Пуска» и его копия на рабочем столе запустили отдельное окно до и после обновления 1.2.0 → 1.2.1. В тестовом профиле оставался один ярлык «Пуска», контрольная сумма не изменилась | Автоматическая установка Edge не создала ярлык «Пуска» в изолированном профиле. Запуск проверен через браузерный протокол, ярлыки требуют ручной проверки |
| Отказ при несовпадении контрольной суммы, отмена обновления, запуск офлайн | Пройдены | Пройдены |

Закреплённые плитки «Пуска», панель задач и запуск после перезагрузки Windows не проверены. В доступных окнах управления оболочка Windows не была представлена. Удаление тестовых установок выполняется теперь и при ошибке теста. После проверок дополнительные ярлыки в «Пуске» и на рабочем столе не остались.

Пройдены 21 автоматический тест, рабочая и тестовая сборки и проверка публичных файлов с локальным списком маркеров. Публичный манифест прочитан для сравнения. Рабочий сайт, ветка `main` и теги остались на опубликованном выпуске.

## Ручная проверка закреплений

На этом компьютере подготовлен отдельный стенд **Start SSB PWA Audit.cmd**. Он слушает только `127.0.0.1:4187`, переключается с 1.2.0 на 1.2.1 по Enter и запоминает состояние для повторного запуска после перезагрузки.

1. Запустите стенд и откройте [127.0.0.1:4187](http://127.0.0.1:4187/) в тестовых профилях Chrome и Edge. Установите приложение **SSB — Проверка ярлыков**. Закрепите его в «Пуске» и на панели задач, создайте ярлык рабочего стола через меню браузера. Закройте окно и проверьте запуск из «Пуска».
2. Если хотите проверить черновик, загрузите учебный каталог из `examples/demo-confluence.json` и сохраните учебное предложение. Нажмите Enter в окне стенда. В каждом установленном приложении нажмите **Проверить обновления → Установить обновление** и подтвердите перезапуск.
3. Проверьте версию 1.2.1 и восстановление черновика. Закройте все окна тестового приложения и браузера. Откройте SSB прежними закреплениями и ярлыком рабочего стола. Ожидается отдельное окно и одна запись в списке приложений каждого тестового профиля.
4. После перезагрузки Windows запустите тот же стенд и повторите проверку ярлыков. После проверки можно убрать приложение **SSB — Проверка ярлыков** из тестового профиля. [Инструкция Microsoft о закреплении PWA](https://learn.microsoft.com/microsoft-edge/progressive-web-apps-chromium/ux)

Для рабочего SSB используйте обычную [инструкцию проверки после обновления](UPDATES.md#проверка-запуска-после-обновления). При похожих ярлыках откройте [ssb.melgaf.com](https://ssb.melgaf.com/) в рабочем профиле и выберите **Открыть в приложении**. Закрепить подтверждённое рабочее окно можно без переустановки.
