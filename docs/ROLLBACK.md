# Восстановление предыдущей рабочей версии

1. Определите последний рабочий тег и дефектную версию. Сохраните ссылки на оба релиза и проверьте, завершился ли выпуск Pages.
2. Верните рабочую реализацию из предыдущего тега в отдельной ветке или отмените конкретные проблемные изменения. Сохраните совместимость с хранилищем пользовательских данных и текущими правилами выпуска.
3. Назначьте номер выше дефектной версии. В `CHANGELOG.md` поясните, какое поведение восстановлено. Это позволяет браузеру получить рабочие файлы по обычному процессу обновления.
4. Прогоните проверку с профилем, в котором предложение уже сохранено дефектной версией. Убедитесь, что черновик открывается после обновления и без сети.
5. Проведите восстановительный релиз по [инструкции выпуска](RELEASING.md). Сообщите менеджерам номер и предложите проверить обновления в приложении.

Сохраняйте опубликованные теги и ZIP прежних релизов как контрольные снимки. При проблемах с установленной версией менеджеры могут временно открыть автономную сборку предыдущего релиза, предварительно скачав настройки и нужные документы из доступной версии. Автономный файл использует отдельное хранилище браузера. Для первой публичной версии предыдущей рабочей версии на Pages ещё нет.
