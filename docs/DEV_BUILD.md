# Локальная тестовая сборка SSB

Для ежедневной разработки в Windows используйте [локальную среду с автоматической пересборкой](LOCAL_DEVELOPMENT.md).

В каталоге проекта выполните `pnpm build:dev` или `node build.mjs --dev`. Откройте `standalone-dev/index.html` напрямую. Для запуска через локальный статический сервер используйте каталог `dist-dev/` и отдельный от рабочего стенда порт.

В шапке видны метка «ТЕСТОВАЯ» и версия `1.1.0-dev`. Заголовок вкладки — «SSB — Тестовая версия». Метка определяется при сборке и отображается при открытии файла и по HTTP.

Тестовая сборка использует собственные ключи настроек и отдельную базу черновиков. У неё отсутствуют манифест PWA и Service Worker. Если обе сборки временно размещены на одном origin, выделите тестовой сборке отдельный путь, например `/test/`. При повторном использовании точного URL ранее установленный рабочий Service Worker может выдать рабочую страницу из кеша. Адрес `http://localhost:4173/` выделен тестовой среде.

`pnpm build` создаёт рабочую версию в `dist/` и `standalone/`. Релизный workflow и `pnpm package` используют эти каталоги. Тестовые каталоги предназначены для локальной работы.

Для проверки обоих вариантов выполните `pnpm build`, `pnpm build:dev` и `pnpm test:dev`. Чтобы использовать установленные браузеры Windows, задайте `SSB_BROWSER_CHANNELS=chrome,msedge` в окружении запуска.

В Chrome и Edge проверено разделение настроек и черновиков по режиму сборки на одном URL при отключённых Service Worker, а также одновременная работа обеих сборок на одном origin по разным путям с активным рабочим Service Worker. В чистом браузерном контексте тестовая сборка не зарегистрировала Service Worker и не запросила `sw.js`.
