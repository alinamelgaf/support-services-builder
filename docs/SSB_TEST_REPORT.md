# Отчёт о тестировании Support Services Builder 1.0.0

Новый проект подготовлен из рабочей браузерной итерации. Перенесены парсер карточек, редактор, естественная сортировка, сравнение трёх пакетов и экспорт. Добавлены импорт трёх типов источников, разделение настроек, PWA и процедура релиза. Для проверки использованы только синтетические данные.

## Результаты

Шесть автоматических тестов на Node.js 24.22.1 прошли. Браузерный сценарий выполнен на Windows в Chrome 157.0.8103.39 и Edge 157.0.4341.42. Тест использовал `file://` и локальный стенд с путём проекта `/support-services-builder/`, чтобы проверить относительные ссылки и область действия Service Worker.

| Сценарий | Подтверждённый результат |
| --- | --- |
| REST и пагинация | Импорт `results` и обёртки `content`, чтение меток и storage, отдельная загрузка нескольких страниц в произвольном порядке, ожидание отсутствующей страницы, устранение повторов, отклонение конфликтующих страниц и неполных меток. Проверен и прежний JSON каталога. |
| Базовая конфигурация | Привязка по ID карточки, параметры из текстовых значений, независимая видимость, предупреждения об отсутствующих ID и отказ от неоднозначного стандарта при дублировании. |
| Вводные тексты | Три варианта, поддержка таблицы со строками или колонками вариантов, списки, абзацы, выделения и внешние ссылки. По умолчанию включён Word. При выборе Extended загружался его текст, после включения Excel он появился в обоих документах. |
| Сортировка и модификации | Проверены TS-1, TS-1.A, TS-2, TS-5.A, TS-10 и TS-10.A. TS-5.A сортируется и редактируется без добавления отсутствующей основной услуги. Новый TS-3.B получил параметр из свежей конфигурации. |
| Конфликты и локальный слой | После нового импорта черновик остался на экране. Проверены отмена применения стандарта, явное применение новых значений и возврат сохранённого параметра менеджера и признака «Включить в документ». |
| Excel | Два листа, отдельные ячейки описания и условий, внутренние переходы по ID и названию, выделение предложения, вводный текст перед таблицей, отсутствие закреплённых колонок на листе «Предложение». |
| Word | Общая таблица, вводный текст выбранного варианта и центрированные текстовые разделы Heading 2. Проверены условия, исключение услуг и отношения гиперссылок. В обоих документах отсутствовали ссылки на учебный Confluence. |
| PWA и установка | Оба браузера разобрали манифест, вычислили ID в пути проекта и не сообщили ошибок установки. Установка и удаление проверены через браузерный протокол в отдельных тестовых профилях. [Диагностика PWA в Chrome](https://developer.chrome.com/docs/devtools/progressive-web-apps) |
| Офлайн и обновление | Без сети открылись приложение и импорт JSON, сформирован Word. Имитировано обновление до 99.0.0. Отмена сохранила черновик. После подтверждения открылась новая версия, настройки пакетов и метки сохранились. После полного перезапуска браузера с тем же профилем без сети открылась новая версия с сохранённым параметром. |
| Сетевое поведение | При автономном сценарии не было HTTP-запросов. Для PWA наблюдались только GET-запросы к локальному адресу приложения. Вложенный `<script>` и удалённое изображение из JSON не выполнялись и не загружались. |
| Состав поставки | Проверены отслеживаемые файлы, две сборки и архивы. Аудит зависимостей после исправлений не сообщил об известных уязвимостях. Подробности приведены в отдельном отчёте безопасности. |

## Воспроизведение

```powershell
pnpm install --frozen-lockfile
pnpm audit --audit-level low
pnpm test
pnpm build
$env:SSB_BROWSER_CHANNELS = 'chrome,msedge'
$env:SSB_NATIVE_INSTALL = '1'
pnpm test:browser
node scripts/check-public.mjs --built
pnpm package
```

Для обычного браузерного прогона достаточно `pnpm exec playwright install chromium` и `pnpm test:browser`. Переменная `SSB_NATIVE_INSTALL` включает дополнительную проверку установки и удаления в тестовом профиле. Для локального сканирования по частным корпоративным маркерам см. инструкцию публикации.

## Что предстоит проверить в рабочей среде

- Фактический JSON корпоративного Confluence Data Center и разметку трёх действующих источников. После импорта проверьте количество карточек и сопоставление нескольких строк с оригиналом в Confluence. При отсутствии `body.storage` или `metadata.labels` понадобится уточнить ответ, который отдаёт рабочая версия REST API.
- Установку пользователем из меню браузера на целевом HTTPS-адресе и ограничения корпоративных политик Chrome или Edge. Локальный тест установки выполнялся через браузерный протокол.
- Выполнение GitHub Actions и публикацию Pages после согласования. Переход на новую версию проверен локально с имитацией смены статических файлов. Самих релиза и размещения на GitHub пока нет.
- Отображение документов в установленном Microsoft Office. Структура `.xlsx` и `.docx`, текст, ссылки и стили проверены программно.

Приложение проверяет полноту по переданным метаданным пагинации. Оно не может определить, скрыты ли карточки из-за прав доступа, неполного CQL-запроса или изменения каталога во время сохранения страниц.
