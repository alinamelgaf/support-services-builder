# Локальная разработка Support Services Builder

## Первый запуск на Windows

1. В Проводнике откройте папку исходников `support-services-builder`.
2. Дважды щёлкните **Start SSB Test.cmd**. Откроется [http://localhost:4173/](http://localhost:4173/). Если браузер не открылся автоматически, откройте этот адрес вручную.
3. Оставьте окно запуска открытым. Для остановки нажмите в нём **Ctrl+C** и подтвердите остановку, если Windows спросит. Повторный запуск откроет вкладку с уже работающей тестовой версией.

На текущем компьютере путь к проверенному Node.js задан в локальном файле `.local/node-path.txt`, зависимости уже установлены. Если при запуске на другом компьютере Node.js или зависимости отсутствуют, установите Node.js 24 LTS. Затем выполните в PowerShell из папки проекта:

```powershell
npm install -g pnpm@11.25.0
pnpm install --frozen-lockfile
```

После установки снова откройте **Start SSB Test.cmd**. [Загрузка Node.js](https://nodejs.org/en/download)

## Проверка изменений

Работа Codex сохраняется в этой же папке. Сервер автоматически пересобирает тестовую версию после сохранения исходников. Когда появится сообщение о готовой сборке, нажмите **Загрузить новую сборку**. Приложение дождётся записи черновика. Если импорт не завершён или настройки источников ещё не сохранены, приложение покажет, что нужно сделать перед обновлением. При ошибке сборки вкладка покажет её причину. Исправление исходников запустит новую попытку.

На `localhost:4173` видны метка **ТЕСТОВАЯ** и суффикс `-dev`. Хранилище настроек и черновиков отдельное. Для проверки используйте файл `examples/demo-confluence.json`. Рабочая версия открывается по адресу `https://ssb.melgaf.com/`.

Если изменится сам сценарий локального запуска или сервера, остановите тестовую среду и снова откройте **Start SSB Test.cmd**.

## От проверки к релизу

Текущие правки и их статус находятся в [журнале неопубликованных изменений](UNRELEASED.md). Проверяйте их в локальной ветке `dev`. После вашего одобрения Codex подготовит новый номер версии, перенесёт выбранные пункты в `CHANGELOG.md` и проверит сборку. Выпуск проводится после отдельного подтверждения через **Publish an approved release**. [Инструкция выпуска](RELEASING.md)
